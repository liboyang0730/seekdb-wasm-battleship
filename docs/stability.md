### 当前重开恢复边界

重开意图在目标库首份快照 `COMMIT` 后才收尾。真实专项覆盖三个故障场景：首次 `notes_main` 创建被真实 1146 错误中断；首份 `current` 快照写入提交前暂停并刷新；首档提交后用真实目录 SQL 故障打断 `finishReset`。

提交前恢复会清理未完成目标库并同名重建，旧库不复活；提交后恢复读取已提交首档，仅完成目录指针收尾，完整 payload 与种子保留，不重建、不换种子。重开错误页同时清理旧侦察派生显示，避免空战役触发渲染异常。本批 13 项检查全部通过，包括首次没有旧库时保留 `oldDatabase=null` 的恢复；源文件起止一致，没有非预期页面／控制台错误或外网请求。

修复前曾有一批 8 项恢复断言通过，但伴随 1 个未捕获页面错误；其备份标识为 `green-before-ui-fix`，不能写成全绿，也不纳入当前通过计数。

A 组两次通过临时响应还原旧关闭／删除路径，均出现上述 `allocation.tmp` 删除诊断；B 组两次使用正常新路径，没有控制台错误。磁盘上的 vendor 文件未因 A 组改写。因此，这 4 次不能写成“当前正式路径连续 4 次零错误”，也不能据此宣称上游断言问题已修复。

- Playwright WebKit 的非持久配置对照在 OPFS 初始化时出现 `UnknownError`，没有进入游戏。这是自动化配置对照，不是原生 Safari 故障结论；原生 Safari 新版 OPFS 仍待补测，Firefox 正式发布版与 Edge 未单独验收。旧内存模式记录不能迁移为新版结论。
- pthread assertion 需要继续观察；`allocation.tmp` 删除诊断仍待解释和复核。现有日志兼容处理不代表修改或修复了上游 Wasm 内核。

- Intel Mac、Windows 的交叉构建和格式检查不能代替对应真机验收；固定端口启动器和最终离线产物应随发布单独核对。

## 历史：v0.1 内存模式专项

以下是旧版资源回收检查，不是新版 OPFS 的表数、内存、关闭或多浏览器验收。旧 21 项与 86 项计数仅用于保留当时证据，不与当前结果累加。

### 旧战役动态表回收

游戏用真实 seekdb 表保存战役笔记、当前状态和 Fork 快照。此前新建战役、换关或重开后，旧表仍留在浏览器内的数据库中；连续三次新战役时，总表数增加到 21、25、29 张。

现在由 `game/资源清理.mjs` 登记成功创建的动态表。每次操作结束，保留当前战役引用的表及其 Fork 祖先，按子表到父表的顺序删除失效表。操作失败时先恢复旧引用，再清理孤立表；删除失败会保留登记，等待下一次操作重试。固定业务表不参与这项清理。

这项修复消除了已复现的旧战役表累积问题，不能据此认定它就是浏览器启动退出的原因。

### 当时的真实引擎复测

在 macOS 上使用独立的 Chromium headless shell 148.0.7778.96、Playwright 1.60.0 和真实 seekdb Wasm 1.4.0.0 验证，没有连接现有浏览器会话。

| 场景 | 结果 |
| --- | --- |
| 同进程空白页停留 10 秒 | 正常 |
| 定位 SQL、追加混合检索，再进入海战 | 正常；对照检索返回向量 3 条、全文 3 条、混合 1 条 |
| Fork 重开及笔记 Merge | 敌位不变，公开笔记的 ID 与正文保留 |
| 重开后连续三次调整并确认部署 | 总表数保持 14、14、14 |
| 连续十次新建战役并确认部署 | 每次部署阶段 9 张、确认后 12 张，不再逐次增加 |
| 换关并确认部署 | 9 张 → 12 张 |
| 人为使第二条 Fork SQL 失败，再恢复重试 | 原状态与快照保留；重试正常 |
| 人为使 DROP 失败，再执行下一操作 | 成功操作没有被回滚，失效表随后被清理 |

上述流程共 21 项检查通过，约 102 秒；没有发现页面崩溃、未捕获脚本错误、异常断连或新增系统崩溃报告。测试中的故意 SQL 错误与 DROP 警告均为预期结果。

资源清理会产生真实 DDL 开销：本轮新建战役约 5 秒，部分 Fork、部署重确认或失败恢复约 9～10 秒。执行期间会锁定重复操作，需等引擎完成。

### 当时的资源与验证边界

该 Wasm 引擎包含数据库运行时和线程，资源占用明显高于普通静态小游戏。本轮浏览器进程树 RSS 求和约 1.4～1.7 GiB；十轮复测期间 Worker 数在暖机后保持 52。RSS 求和包含共享页的重复计数，不能当作独占内存；短时复测也不能证明长时间绝无内存增长。

已验证的是列出的版本、操作路径和测试时长。Chrome、Safari、Firefox 的接入验证情况见 [README](../README.md#兼容性与第三方来源)。Windows 与 Intel Mac 尚无对应真机验收记录；本记录不构成所有浏览器版本、低内存设备或任意持续时长的零崩溃保证。
