# 本地存档与重开新游戏

本版用真实 seekdb WebAssembly 将完整战役保存到浏览器 OPFS。舰队与敌位、伤害、弹药、关卡、勋章、试错次数和冷却、查询结果、战术线索、标记、战报及 Fork 状态都随存档恢复。本轮增加的是存档与恢复能力，舰队、武器、关卡和胜负规则不变。

## 刷新后继续同一局

使用同一浏览器、同一用户配置和同一地址重新打开游戏，等待引擎就绪后，会读取最近成功保存的状态。部署中的阵型和选择、查询后带回的线索、海战结果、领奖状态及 Game Over 都属于可恢复状态。

以页面的保存成功提示为准。保存中或写入报错时，不代表最后动作已经成功落盘。刷新不是撤销：已保存的消耗、伤害和试错冷却不会消失。若炮击已有待处理记录，恢复流程会完成该次行动；专项检查覆盖了中途失败后再次刷新只结算一次的路径。

换关、Fork 试错、胜利或失败不会自动删除战役库。Game Over 结果会保留，刷新也不会自动洗成新局。

## 每局一个真实数据库

当前战役库使用唯一名称 `seekdb_naval_时间戳`。首次开局执行实际 `CREATE DATABASE`，存档目录库 `seekdb_naval_catalog` 记录当前战役与未完成的重开请求；刷新读取原库，不另建一局。

验收记录中的一次真实重开执行了：

```sql
DROP DATABASE IF EXISTS `seekdb_naval_1794487518213`;
CREATE DATABASE `seekdb_naval_1794490113741`;
```

这些是该次测试的数据库名，不是每个人共用的固定库名。删除旧战役后，目录库保留，用于指向新局。完整状态和历史记录通过真实 SQL 写入 seekdb，不是只给浏览器对象贴上数据库名称。

## 只有“重开新游戏”删除旧局

顶栏入口在教学、部署、情报、航海图、交战及结果页始终可见。手册弹窗的置顶标题栏也有重开按钮，读到末尾仍可点击；重开成功后关闭弹窗。按钮直接执行，没有第二次确认弹窗：

1. 点击前确认愿意放弃旧战役。
2. 若查询、保存或行动仍在执行，先等待旧操作完成或回滚，再实际删库，避免与旧事务并发删除。
3. 实际删除旧战役库，创建新的独立库并保存第一关部署状态。旧局的勋章、伤害、弹药、笔记和进度不迁移。

首次开局没有旧数据库时也支持中断恢复；`oldDatabase=null` 会保留原意，不会误认为新旧数据库相同。13 项专项回归覆盖这一路径及下面的初始化、提交和目录收尾边界。

旧档写入失败时仍可提出重开。删除或创建失败时，页面保留恢复信息并阻止继续操作未完成切换的旧局；重开请求已保存后再刷新，会继续这次重开，不会把它当作撤销。故障注入检查覆盖了 `DROP` 失败后恢复到同一个预定新库，而不是不断创建新库的路径。

恢复以首份新局快照是否已经 `COMMIT` 为界：提交前失败或刷新，会清理未完成的目标库，再以同名重建；首档已提交、只是目录收尾失败，则读取已提交快照，仅完成目录指针收尾，保留原种子和状态，不重建、不再随机。重开意图在首档提交后才完成；错误页会清除旧局派生的侦察显示，避免拿空战役继续渲染旧线索。

“试错机会”是保留本战役数据库、按规则重开当前关的另一项能力，不等于删除整个战役。

## 同一浏览器、同一地址

原生启动器固定使用 `http://127.0.0.1:8876/`，端口冲突时不会自动换端口。源码服务默认的 `http://127.0.0.1:8768/` 是另一个存档空间。

浏览器按协议、主机名和端口区分存储。因此 `localhost` 与 `127.0.0.1`、8876 与其他端口、不同浏览器或用户配置都不会自动共享存档。不要用换端口绕过占用来寻找旧进度。

持久数据库需要 OPFS 与 Web Locks。同一地址只允许一个标签页或窗口持有这份数据库；提示占用时，关闭原标签页或窗口，稍候后刷新。不要清理网站数据来解除占用，那会连存档一起删除。

## 存储边界

这是本浏览器的本地存档，不是跨设备、跨浏览器云同步。**清理网站数据会删除存档**；隐私窗口结束时数据也可能被移除。持久存储保护请求可能被浏览器拒绝，存储配额和磁盘错误也可能阻止写入。不能承诺异常退出、断电或存储被清理后绝不丢失。

查询只向玩家展示本作允许公开的粗线索与回执；保存完整裁判状态不改变线索公开规则，也不意味着 SQL 向玩家直接返回隐藏舰位。

## 本轮实际验证

2026-11-12，当前验收完成 125/125 项 Node 检查、最终离线单页 11/11 项检查，以及真实重开恢复专项 13/13 项检查。最终单页验证手册弹窗实际重开、正常炮击、3 次刷新及 3 次关闭浏览器进程后恢复，完整战役、当前存档行与历史表指纹一致，并实际执行删旧库、建新库；该批页面／控制台错误及外网请求均为 0。

重开专项通过真实 SQL 故障覆盖三个时点：首次动态表创建失败、首份快照提交前中断、首档提交后的目录收尾失败。13 项检查均通过，没有非预期页面错误、控制台错误或外网请求。此前一批曾有 8 项恢复断言通过但同时出现 1 个未捕获页面错误，属于修复前记录，不能称全绿。

此前 12 项完整状态、6 项画面与坐标、8 项全阶段界面检查仍按各自版本保留，覆盖领奖、Fork 冷却、Game Over、行动中重开等场景；不与当前结果累加。换关与胜负场景使用明确夹具，不代表玩家自然通关记录。

源码版 Chromium、Playwright Firefox 与 Playwright WebKit 三类引擎已有真实 OPFS 实测；后两者各 4/4 项验证启动、建库和混合检索入战、刷新恢复与实际删库重开。最终离线单页已在 Playwright Firefox 与持久配置 WebKit 中各通过 4/4 项检查，包含真实引擎、混合检索、问号标记、刷新指纹一致和实际删库建库；包文件 SHA-256 与两个 ZIP 内的 HTML 一致。Playwright WebKit 不代替原生 Safari；原生 Safari 新版 OPFS、Firefox 正式发布版和 Edge 未单独验收。Firefox 保留 Wasm 弃用警告。

关闭引擎时曾发生一次 pthread assertion，后续 A/B 共 4 次未复现，但不能宣称上游问题已修复。SDK 句柄辅助代码新加异步所有者代次保护，防止旧异步完成回调覆盖复用槽位；这不是 pthread 修复。较早完整状态批次保留的一条临时文件删除诊断也未被当前通过结果抹去。详细批次与边界见[稳定性验证记录](stability.md)。
